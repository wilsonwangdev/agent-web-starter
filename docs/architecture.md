# 架构与职责

这是具有一个只读工具的 Agent Web 示例。React 负责会话界面，AI SDK 负责消息、流式传输和模型工具调用。通用服务处理器通过 Cloudflare Worker、Pages Functions 或 Vercel Functions 接入。根应用保留 Vite 标准入口；项目不维护另一套聊天流协议或开发服务器。

## 请求如何执行

```text
用户发送消息
  → useChat + DefaultChatTransport
  → POST /api/chat
  → 服务端核对模式、配置和请求
  → 演示流程，或真实模型与工具调用
  → AI SDK 消息流
  → 文本与工具结果呈现
```

演示模式执行固定的示例流程，实际调用 `getTemplateInfo` 读取公开项目元信息和服务时间，随后流式返回固定说明。它用于检验界面和服务接线，不代表模型理解了任意问题。工具不读取任意文件、不运行命令。

真实模型模式由服务端显式启用。模型生成与工具调用使用 SDK 能力，工具在服务端按校验后的参数执行。配置或访问口令不完整时返回明确错误，保留原会话；不静默切换成演示回答。取消、错误和重试由 SDK 生命周期与项目交互共同处理，迟到结果不能覆盖另一个会话。

聊天失败按 SDK 保留的 HTTP 状态选择本地化说明，不展示任意服务端错误文本。访问口令错误可修正后重试原消息；请求或会话过大时保留记录与草稿，提示缩短内容后新建对话。

## 模块归属

- `src/main.tsx` 启动应用、提供器和路由；`src/App.tsx` 组合页面与共享能力。
- `src/chat/` 维护聊天交互、消息呈现和 SDK 生命周期。`ChatPage` 先维护空首页、草稿与待发送意图，首次发送或恢复真实消息时才加载 `ChatSession`；后者通过官方 SDK 维护请求和消息流。`ChatFooter` 共享输入、口令与状态界面。加载期间取消或导航会使旧意图失效，交接不重复发送、不自动重放刷新前的请求。
- `src/preferences/`、`src/i18n/`、`src/pwa/` 分别维护界面偏好、语言资源和安装事件，不依赖聊天业务实现。
- `worker/api.ts` 维护通用请求边界，`worker/` 内其他模块维护配置、工具和模型接入；`worker/index.ts`、`functions/`、`api/` 只适配各平台。模型凭据及访问口令校验留在服务端。
- `shared/` 维护公开元信息、必要的跨端类型及数据定义；服务实现和界面实现不反向进入共享层。
- `packages/ui/` 是本仓库私有的基础组件源码包，应用通过 `@agent-web-starter/ui` 的公开导出消费。

优先沿现有模块扩展具体业务。状态靠近拥有其生命周期的模块，入口保持组装职责；工具执行、会话存储和界面展示各自独立变化，不把整个流程迁入一个大 Hook。

`index.html` 先呈现无业务内容的结构骨架，`src/startup.css` 直接提供其样式；`src/bootstrap.ts` 仅通过原生动态导入加载主应用并处理加载失败。`src/startup/recovery.ts` 同时服务于 HTML 入口下载失败和模块、React 根错误恢复，不接管聊天错误或增加计时器。React 首次提交替换静态骨架，历史校验期间由 `app/ChatLoading.tsx` 只占位内容区；主入口继续只负责挂载。

## 接口与配置

`POST /api/chat` 使用 AI SDK 的消息与流式响应格式。新增内容先核对 SDK 的消息部分和工具类型，保留输入校验，不另造与 SDK 重复的消息协议。

`GET /api/config` 只返回界面需要的能力状态，不返回密钥或完整服务配置。安装清单由 `build/public-assets.ts` 从公开投影生成静态文件；原 `/api/manifest.webmanifest` 仍可读取根路径清单。默认服务部署使用浏览器路由回退，GitHub Pages 构建使用官方哈希路由。

`src/deployment.ts` 只读取公开构建配置，选择同源或显式指定的后端源地址。服务端跨域白名单独立配置。没有后端的 Pages 构建只呈现界面预览，不能执行工具或发送模型请求。

模式、环境变量和部署范围统一见[服务配置与部署](deployment.md)。本示例提供 Web 服务，不代表已经连接任何开发工具中的当前 Agent 会话，也不跨宿主读取工作区。

Pages 使用根 `wrangler.jsonc`，Worker 使用 `wrangler.worker.jsonc`。静态构建通过成熟清理工具仅移除 Cloudflare 插件生成的部署重定向文件，使 Pages 不会误读上次 Worker 的配置；本地状态和私密变量不受影响。各部署命令输出独立产物，不上传整个 `dist/`：页面只发布 `dist/static/` 或 Worker 的 `dist/client/` 资源。

## 工程与检查边界

`package.json` 维护项目身份、产品版本、命令与运行要求。公开元信息由 `shared/project.ts` 投影，浏览器只接收需要的字段。Vite+ 关联依赖通过清单引用工作区 catalog；其他依赖由各包清单维护，锁文件记录解析结果。

UI 包由应用编译源码，不独立发布。React 与 React DOM 由应用提供统一实例；主题值和偏好状态留在应用。组件 CSS 显式引入并声明副作用，私有实现不通过深层路径消费。

类名合并使用 `cn/engine` 和上游完整预编译规则表，保留 `ui:` 前缀与覆盖语义，不在浏览器编译配置。路由使用本应用实际需要的官方声明式模式；记录校验继续使用 SDK 的正式验证能力，空历史和纯草稿不触发 SDK 下载。设置与 Markdown 也按实际打开或显示时机加载。体积评估统计可交互首屏的全部资源，不以薄启动入口的大小代替整体成本；优化不能减少运行时校验或通过调整告警阈值掩盖问题。

界面偏好、公开配置与本地历史外层使用官方 `zod/mini`，保持同样的字段、限制和回退；SDK 及服务端继续使用其兼容的校验实现。这样把完整校验器的前端成本留到实际对话阶段，接受少量完整会话总量增加以减少空首页加载。新增校验时沿已选 API 扩展，不自行实现消息解析或省略边界验证。

为避免受测 WebKit 对失败的模块预加载保留负缓存，使用 Vite 正式配置关闭额外 `modulepreload`，保留原生动态导入与异步样式加载。模块失败由使用者主动重新加载，不通过随机地址或自动刷新绕过失败。

`tooling/lint.ts` 维护依赖方向、运行环境隔离和循环依赖检查。浏览器、共享层和 Worker 使用各自的 TypeScript 环境；浏览器不读取完整清单、服务源码或 Node 工具，共享层与 Worker 不导入 UI 包。导入文本限制不等于完整路径解析；新增别名或入口后验证正反案例，区分纯类型与运行时依赖。

Vite+ 组合已有静态与格式规则，Stylelint 检查设计变量，`tsc -b` 覆盖各 TypeScript 项目。Husky 和 lint-staged 保留暂存隔离与恢复，提交与 CI 调用项目清单中的同一检查入口。

普通构建和完整验收实际执行；可选构建缓存只复用明确的构建任务。维护缓存配置时核对组件源码、公开资源和产物范围，验证相关输入变化后的失效、命中后的产物恢复及禁用缓存对照。命中日志不作为本次测试执行证据。

本地会话的数量、每条会话消息数和总保存大小受 `src/chat/storage.ts` 限制；达到限制或浏览器写入失败时明确提示，保留当前页面内容，不通过自动删除旧会话腾出空间。持久化范围仅为当前浏览器，不承诺跨设备同步。

恢复已有消息时才按需下载 SDK 校验器。模块下载失败与记录格式损坏分别处理：下载失败时阻止编辑和保存，提供主动重新加载，避免空状态覆盖有效历史；恢复记录不会自动发送刷新前未完成的请求。

## 验证范围

Node 测试验证公开投影与可独立数据规则；Worker 测试验证请求、配置、工具及 SDK 流；浏览器组件测试验证真实交互；生产 Playwright 流程验证发送、工具结果、取消、失败恢复、会话导航和代表性语言、主题、移动视口。

模拟模型用于重复检验成功、错误和取消，不证明真实服务已经接通。安装基础、浏览器移动模拟和实体设备验收分别报告；运行记录留在本地或 CI，不写成模板规则。
