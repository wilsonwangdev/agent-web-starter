# 从示例开始

先按 README 启动演示，发送一条消息，观察回复和 `getTemplateInfo` 工具结果，再体验取消与重新发送。界面的演示标记表示这条流程没有调用语言模型。

建立派生项目时：

1. 复制模板代码或从模板仓库创建独立项目，沿 `AGENTS.md` 读取开发约定。
2. 在根 `package.json` 修改项目名称、版本、说明和 `product`。仓库地址与问题入口只填写真实存在的地址；网页、服务及安装清单继续从公开投影读取元信息。
3. 选择独立、稳定的 `product.storageNamespace`。展示名称可以调整；已上线后变更存储键需要明确迁移方案，不自动清除旧数据。
4. 如需更改 UI 包名，同步包清单、两份 `components.json`、消费者导入及模块边界规则，并验证合法与违规引用。
5. 替换 `public/favicon.svg`，使用 `pnpm assets:generate` 生成图标；保持安装清单、页面和图标一致。
6. 确定一条实际业务流程，替换示例提示和工具。工具的输入、执行范围、结果及错误一并维护；涉及外部写入时先设计权限与确认方式。
7. 按[服务配置](deployment.md)选择演示或真实模型模式，完成贡献指南中的检查，再通过 PR 发布改动。

本示例与 [web-starter](https://github.com/wilsonwangdev/web-starter) 各自维护完整源码、清单和上下文。模板用于创建独立项目，后续升级按需对比并在自己的分支验证，不自动覆盖业务代码，也不依赖相邻目录中的另一份检出。

默认构建使用浏览器路由；GitHub Pages 模式已通过哈希路由适配项目子路径，资源与安装清单跟随 Vite 基路径。构建方式与直达、刷新验证见[部署说明](deployment.md#github-pages前端预览或连接独立后端)。
